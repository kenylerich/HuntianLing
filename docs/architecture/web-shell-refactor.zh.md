# Web 界面重构计划

[English](web-shell-refactor.md) | 中文

## 摘要

当前浏览器 UI 是一个页面，用显隐切换七个敏捷工作台。它没有拆客户、开发、管理员。功能挤在同一份 HTML 里，页面说不清自己在服务哪一项工作。本计划记录代码诊断和替换该壳的切片。产品需求仍在 [backlog](../requirements/backlog.zh.md)；本页负责 UI 重构顺序。

## 代码诊断

依据 `src/host/web/page.ts`（约 12,200 行：CSS、标记和脚本写在同一个 `renderBoardPage()` 字符串里）和 `src/host/web/server.ts`（约 5,200 行看板聚合）。

| 问题 | 代码实际在做什么 | 为什么不符合产品 |
| --- | --- | --- |
| 没有人群界面 | 登录只设置 `body.auth-locked`，把除设置外的轨道按钮变灰。会话主体有 `roles` 和 `projectIds`，没有 `customer` / `developer` / `admin`。 | `REQ-WEB-007` 要求登录后三套界面。一块驾驶舱不是那个产品。 |
| 分类是项目管理模块，不是工作 | 轨道：录入、Backlog、计划、团队、运行、证据、管理。每个区域仍共用页头、健康条、看板画布、检查器和侧栏。切换区域只是把 `data-area-panel` 设为 `hidden`，其余页面还在。 | 用户分不清自己是在收集、设计、看进度，还是在管理。 |
| 功能堆在一份文档里 | 新建工作项、录入会话表单、里程碑表单、团队表单、项目表单、登录、API token、需求树、健康指标、CRUD 矩阵和审计都在同一份标记里。检查器标签是长列表（摘要、分析、设计、验收、来源、子项、审计）。 | 扫视成本高。空的或不相关的控件仍占布局。 |
| 文案不像这个产品 | 区域负责人是 PO/BA、Scrum Master、QA。阶段是 “Backlog refinement” 和 “E2E delivery run”。标题是 “HuntianLing Board”。 | 产品是带标准开发看板的 vibe coding harness，不是 Azure Boards 仿品。 |

`REQ-WEB-006` 已经拆过工作区。那次拆分是同一块开发驾驶舱上的 CSS 显隐。它没有实现人群界面、客户的 MKT 对话框，或 Agent 频道。

## 目标界面

一个 Web 源、一次登录、三份文档或三条路由界面。同一组 WorkItem 记录。

| 界面 | 谁 | 主要工作 | 导航 |
| --- | --- | --- | --- |
| 客户 | `audience=customer` | 创建自己的项目；与 MKT 对话；查看原始需求；查看客户侧进度 | 项目、对话框、我的需求、进度 |
| 开发 | `audience=developer` | 收集、设计、查看交付进度、在 Agent 频道交流、绑定环境 | 收集、设计、进度、频道、环境 |
| 管理员 | `audience=admin` | 用户、归属、环境就绪、插件配置、审计 | 用户、项目、环境、访问、审计 |

客户侧进度仍是：已提出 / 待客户确认 / 分析中 / 开发中 / 已交付。开发的「进度」可以把运行和证据做成同一工作的两个视图，而不是两个顶级产品。管理员不以编辑需求正文为主工作。

每个界面的布局规则：轨道上一项工作、一块主画布、一个只显示该工作字段的检查器。创建动作属于拥有该记录的工作。

## 不要做的事

- 不要只给七模块轨道换皮肤就声称重构完成。
- 不要把所有表单留在一份 HTML 里再隐藏。
- 不要把 Agent 频道或环境搭建放到客户界面。
- 不要把业务 CRUD 覆盖表放到开发者日常页。
- 不要继续增大 `page.ts`。新界面用新模块。

## 重构切片

用 WorkItem 跟踪这些切片。每个切片写明 `REQ-*` 和退出检查。切片 1 还不能按人群路由时，不要开始切片 2。

### 切片 0 — 拆开页面模块

文件：把 `src/host/web/page.ts` 拆成壳标记、CSS 和视图脚本。不要求用户可见变化。

退出：`page.ts` 只做组合；CSS 和工作区脚本作为独立模块加载。单元测试仍能渲染看板页。

### 切片 1 — 登录和人群路由

需求：`REQ-WEB-007`、`REQ-AUTH-001`。

- 在会话主体上持久化 `audience`：`customer`、`developer`、`admin`。
- 登录后只打开该界面。其他界面返回授权错误。
- 未登录用户只看到登录，看不到变灰的驾驶舱。

退出：三个用户、三个落地页；猜 URL 进入其他界面被拒绝。

### 切片 2 — 客户界面

需求：`REQ-WEB-007`、`REQ-MKT-001`、`REQ-INTAKE-001`、`REQ-HARNESS-008`。

- 只创建和打开该客户的项目。
- MKT 对话框是主画布。
- 「我的需求」列出带原话的原始需求。
- 进度使用来自证据的客户侧标签，不是手改摘要。

退出：客户能提交对话、看到自己的话、看到进度，且没有 Backlog、团队、运行、证据或管理导航。

### 切片 3 — 开发界面重排

需求：`REQ-WEB-007`、`REQ-REQ-001`、`REQ-HARNESS-001`、`REQ-COLLAB-001`、`REQ-COLLAB-004`。

用五项工作替换七模块轨道：

| 工作 | 展示 | 不展示 |
| --- | --- | --- |
| 收集 | MKT 会话和原始需求（开发视图） | 仅客户文案；管理 CRUD |
| 设计 | 分析、设计、验收、拆分 | 把门禁矩阵当首页 |
| 进度 | 运行、阻塞、证据作为交付的视图 | 把团队 WIP 当成并列产品 |
| 频道 | Agent 频道（`REQ-COLLAB-004`） | 客户 MKT 历史 |
| 环境 | 配置、就绪、阻塞、仓库绑定 | 插件 auth token 管理 |

检查器标签跟随当前工作。团队分配可以放在设计或进度的面板里，不要做成顶级产品。

退出：开发者能收集、打开设计、看进度、打开频道，而不再看到录入/Backlog/计划/团队/运行/证据/管理这一条带。

### 切片 4 — 管理员界面

需求：`REQ-WEB-007`、`REQ-AUTH-001`、`REQ-AUDIT-001`。

- 用户和人群分配。
- 项目归属。
- 跨项目的环境就绪。
- 插件和访问设置。
- 审计轨迹。

退出：登录、给客户建项目、CRUD 覆盖不在开发者的收集或设计页上。

### 切片 5 — 拆除融合驾驶舱

- 从客户和管理员界面删除无用轨道、健康堆砌和常驻新建器。
- 每个界面内部仍遵守 `REQ-WEB-006`：一块主画布、一个检查器。
- 更新 [主看板设计](main-board-design.zh.md)，使其视图目录属于开发界面，而不是唯一 UI。

退出：客户/管理员标记里 `git grep` 不到 `module-rail`；开发标记里管理/CRUD 不再是并列工作。
